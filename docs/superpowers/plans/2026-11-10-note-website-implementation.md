# SQL × Python 笔记网站实施计划

日期：2026-11-10  
依据：`docs/superpowers/specs/2026-11-10-note-website-design.md`

## 实施原则

- 原始笔记只读，不自动改写。
- 先用测试固定解析规则，再实现解析器。
- 每完成一个阶段都生成可检查的结果，不把问题积累到部署阶段。
- 使用原生 HTML、CSS、JavaScript 和 Python 标准库；除非 Markdown 展示确有必要，不增加依赖。
- 第一版只实现已确认的功能，不加入登录、数据库和在线编辑。

## 阶段 1：建立项目骨架与基线

### 任务

1. 初始化本地 Git 仓库。
2. 创建 `site`、`scripts`、`config`、`tests` 和 `.github/workflows` 目录。
3. 添加适合 Python 和静态网站的 `.gitignore`。
4. 保存当前原始笔记状态，确保后续整理程序不会修改源文件。

### 验证

- Git 能识别工作区。
- `daily_note.md` 和 `practice.py` 的内容哈希在构建前后保持一致。
- 项目目录中没有生成缓存或临时文件被误提交。

## 阶段 2：定义知识点数据格式

### 文件

- 新建 `config/knowledge-map.json`。
- 新建 `scripts/build_notes.py`。
- 新建 `tests/test_build_notes.py`。

### 任务

1. 定义知识点字段：标识符、标题、模块、分类、摘要、记录、代码、日期、来源、别名、整理提示、搜题关键词和精确题目链接。
2. 定义人工配置格式，只保存分类纠正、别名、提示和精确链接。
3. 编写最小数据校验函数。

### 验证

- 合法的最小知识点数据通过校验。
- 缺少必要字段、重复标识符和错误链接格式会给出明确错误。

## 阶段 3：解析 `daily_note.md`

### 先写测试

- 能识别日期标题。
- 能识别 SQL/Python 模块标题。
- 能按知识点标题切分内容。
- 能保留代码块、列表和普通段落。
- 缺少模块标题的片段不会丢失。

### 实现

1. 按行读取 Markdown，不修改源文件。
2. 建立日期、模块和知识点标题状态。
3. 将连续内容组合成原始记录。
4. 为无法可靠判断的内容保留待整理记录。

### 验证

- 对完整 `daily_note.md` 运行解析。
- 抽查字符串处理、分组取极值、窗口函数、JOIN、日期函数等主题。
- 解析前后源文件哈希一致。

## 阶段 4：解析 `practice.py`

### 先写测试

- 能识别日期注释。
- 能识别编号主题和小节标题。
- 能把注释说明与示例代码组合为知识点。
- 不执行 `practice.py` 中的任何代码。
- 模糊片段进入待整理。

### 实现

1. 使用 Python 的分词能力读取注释和代码位置。
2. 根据日期、编号标题和主题词确定知识点边界。
3. 保留示例代码及相邻说明。
4. 默认归入 Python 模块，明确标记为 SQL 的片段除外。

### 验证

- 抽查条件判断、循环、列表、字典、集合、深浅拷贝和函数等主题。
- 验证构建过程没有产生交互输入或执行输出。
- 解析前后源文件哈希一致。

## 阶段 5：分类、合并与人工纠正

### 先写测试

- 典型 SQL/Python 关键词进入预期分类。
- 中英文别名参与搜索字段生成。
- 人工配置优先于自动规则。
- 同主题多日记录合并后仍保留各自来源。
- 未识别内容进入“待整理”。

### 实现

1. 建立最小关键词分类表。
2. 规范化知识点名称并生成稳定标识符。
3. 合并相同主题的记录。
4. 应用 `knowledge-map.json` 中的人工纠正。
5. 生成牛客和力扣搜索关键词与链接。
6. 输出 `site/data/notes.json`。

### 验证

- 所有提取出的有效片段均进入最终数据或明确的待整理列表。
- 标识符唯一，链接格式正确。
- 输出 JSON 可被浏览器读取。

## 阶段 6：实现静态网站

### 文件

- 新建 `site/index.html`。
- 新建 `site/styles.css`。
- 新建 `site/app.js`。

### 任务

1. 实现首页、SQL/Python 模块切换和知识点数量展示。
2. 实现分类导航和知识点卡片。
3. 实现卡片展开、原笔记、代码、日期和来源展示。
4. 实现全文搜索、关键词高亮及模块/分类筛选。
5. 实现牛客、力扣搜索入口和可选精确题目链接。
6. 实现手机响应式布局和浅色/深色模式。
7. 对用户笔记内容进行安全转义。

### 验证

- 搜索“窗口函数”“JOIN”“循环”“列表”“函数”均有合理结果。
- 清除筛选后能恢复完整列表。
- 外部链接使用安全的新窗口配置。
- 手机和桌面宽度下没有横向溢出或无法操作的控件。

## 阶段 7：内容审查与分类修正

### 任务

1. 对当前完整笔记运行构建。
2. 统计 SQL、Python、各分类和待整理数量。
3. 抽查每个主要分类的知识点卡片。
4. 只通过 `knowledge-map.json` 修正特殊分类、别名和整理提示。
5. 确认网站显示的内容均能追溯到原始文件。

### 验证

- 当前有效笔记没有静默丢失。
- 主要主题分类正确。
- 待整理内容数量和原因清楚可查。
- 原始笔记未被修改。

## 阶段 8：自动化测试与本地验收

### 任务

1. 运行全部 Python 单元测试。
2. 运行完整构建两次，确认输出稳定。
3. 启动本地静态预览。
4. 检查浏览器控制台错误、搜索、筛选、展开和外链。
5. 检查常见手机和桌面尺寸。

### 验证

- 测试全部通过。
- 两次构建得到相同的知识点标识符和分类结果。
- 页面无阻断使用的脚本错误。
- 本地预览满足设计文档中的完成标准。

## 阶段 9：配置 GitHub Pages

### 文件

- 新建 `.github/workflows/deploy-pages.yml`。
- 新建 `README.md`，记录更新笔记和发布方式。

### 任务

1. 配置在主分支推送时运行测试和笔记构建。
2. 测试通过后上传 `site` 目录并发布 GitHub Pages。
3. 失败时阻止覆盖上一版网站。
4. 在 README 中写明 GitHub 仓库创建、首次推送和 Pages 设置步骤。

### 验证

- 工作流语法有效。
- 本地生成的发布目录不依赖本机绝对路径。
- 用户连接 GitHub 仓库后，推送可以触发自动发布。

## 阶段 10：线上验收

### 任务

1. 打开公开 GitHub Pages 地址。
2. 分别在电脑和手机访问。
3. 验证 SQL/Python 模块、搜索、筛选、详情和搜题入口。
4. 对笔记做一次小更新并推送，确认网站自动更新。

### 完成标准

- 公开网址可访问。
- 当前有效笔记均可搜索或浏览。
- 自动分类与人工纠正按预期生效。
- 更新源文件并推送后，线上内容自动刷新。
- GitHub Actions 失败时不会覆盖可用版本。

## 实施中的暂停点

以下情况需要暂停并请用户决定：

- GitHub 仓库名称和公开网址尚未确定。
- GitHub 登录或授权需要用户本人完成。
- 原始笔记中的某段内容存在两种同样合理但含义不同的分类。
- 第三方网站限制搜索链接或改变公开地址格式。

除此之外，各阶段按测试结果连续推进。
