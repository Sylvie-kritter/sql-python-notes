# SQL × Python 笔记网站设计

日期：2026-11-10

## 1. 项目目标

把现有的 `daily_note.md` 与 `practice.py` 整理为一个可在手机、平板和电脑访问的公开学习网站。网站以用户的原始笔记为唯一主要内容源，不另写一套脱离笔记的教程。

第一版必须满足以下目标：

- 将内容分成 SQL 与 Python 两个一级模块。
- 将零碎笔记归纳成可浏览、可搜索的知识点。
- 保留知识点的原文、代码、日期和来源文件。
- 为每个知识点提供牛客网与力扣的搜题入口。
- 更新源文件并提交到 GitHub 后，网站自动整理并重新发布。
- 使用 GitHub Pages 免费公开部署。

## 2. 范围

### 2.1 第一版包含

- 首页、SQL 模块页、Python 模块页。
- 全文搜索、模块筛选和分类筛选。
- 知识点卡片及展开后的完整笔记内容。
- 自动分类、人工纠正、搜索别名和题目链接配置。
- 响应式布局及浅色、深色模式。
- GitHub Actions 自动构建和 GitHub Pages 自动发布。
- 解析、数据校验和页面冒烟测试。

### 2.2 第一版不包含

- 登录、注册和多用户权限。
- 在线编辑笔记。
- 评论、收藏、学习打卡和云数据库。
- 依赖外部 AI 接口的自动分类。
- 自动抓取牛客或力扣题库内容。

这些功能只有在第一版实际使用后出现明确需求时再考虑。

## 3. 内容原则

1. `daily_note.md` 和 `practice.py` 是原始内容源，整理程序只读取，不修改。
2. 分类和页面排版可以调整，但不得静默改写原笔记的含义。
3. 同一知识点在不同日期重复出现时集中展示，同时保留每一段原始记录及来源。
4. 明显的错别字或概念问题保留原文，并以单独的“整理提示”呈现。
5. 无法可靠分类的内容进入“待整理”，不得被丢弃。

## 4. 信息架构

### 4.1 一级模块

- SQL
- Python

### 4.2 初始分类

SQL 初始分类：

- 查询基础
- 字符串处理
- 分组与聚合
- 多表连接
- 窗口函数
- 日期与数值函数
- 表结构与数据修改
- 事务、锁与存储过程
- 待整理

Python 初始分类：

- 基础语法与数据类型
- 输入、输出与格式化
- 运算符与条件判断
- 循环
- 字符串
- 列表、元组、字典与集合
- 函数
- 拷贝与可变性
- 待整理

分类以当前笔记内容为起点。将来出现新主题时，可通过配置文件新增分类，不需要修改原笔记。

## 5. 页面设计

### 5.1 首页

- 网站名称与简短说明。
- 全局搜索框。
- SQL、Python 两个模块入口及知识点数量。
- 最近更新的知识点。
- 笔记来源和最后构建时间。

### 5.2 模块页

- 桌面端左侧显示分类导航，右侧显示知识点列表。
- 手机端将分类导航改为顶部筛选按钮。
- 支持按分类筛选，并显示结果数量。
- 知识点卡片显示标题、分类、摘要、日期和来源。
- 展开卡片后显示完整原文、代码、整理提示及练习入口。

### 5.3 搜索

- 搜索范围包括标题、正文、代码和别名。
- 支持继续按 SQL/Python 和子分类筛选。
- 结果中的匹配关键词高亮。
- 搜索“排名”等中文别名时，可以命中 `ROW_NUMBER`、`RANK` 等相关知识点。
- 无结果时给出清晰提示并允许一键清除筛选。

### 5.4 练习入口

每个知识点至少提供：

- “去牛客搜题”：使用整理后的中文关键词打开牛客搜索。
- “去力扣搜题”：使用中英文关键词打开力扣搜索。

配置文件可以为知识点补充精确题目名称和链接。第一版不抓取第三方页面内容，避免题库页面变化导致网站失效。

## 6. 内容处理流程

```text
daily_note.md + practice.py
        ↓
解析标题、注释、日期、正文和代码
        ↓
拆分知识点并识别 SQL / Python
        ↓
关键词分类 + 人工纠正配置
        ↓
合并同主题记录并生成搜索字段
        ↓
输出静态网站数据
        ↓
构建并发布 GitHub Pages
```

### 6.1 Markdown 解析

- 根据日期标题、SQL/Python 模块标题和知识点标题切分 `daily_note.md`。
- 保留代码块、列表、表格和段落的原始顺序。
- 记录来源文件及源文件中的日期。

### 6.2 Python 笔记解析

- 将 `practice.py` 中的注释视为笔记正文。
- 根据日期注释、编号标题和主题标题划分知识点。
- 保留注释中的示例代码；不执行 `practice.py`。
- 无法判断边界的连续内容归入一个待整理片段，避免误拆和丢失。

### 6.3 分类与合并

- 先依据明确的 SQL/Python 标题判断模块。
- 再依据知识点名称、函数名和关键词判断子分类。
- 人工配置的判断优先于自动规则。
- 具有相同规范化主题名的记录在页面中合并展示，但每条记录仍保留独立来源信息。

### 6.4 人工配置

使用一个小型配置文件维护：

- 特定知识点的模块或分类纠正。
- 搜索别名。
- 整理提示。
- 牛客和力扣的精确题目链接。

配置只覆盖需要纠正的特殊情况，不复制整份笔记内容。

## 7. 技术设计

### 7.1 总体方案

- 前端：原生 HTML、CSS、JavaScript。
- 整理程序：Python。
- 内容产物：构建时生成的 JSON 数据。
- 托管：GitHub Pages。
- 自动化：GitHub Actions。

不使用前端框架、后端服务或数据库。搜索和筛选在浏览器中完成，适合当前笔记规模，部署和维护成本最低。

## 8. 自动更新与发布

1. 用户修改 `daily_note.md` 或 `practice.py`。
2. 用户将变更提交并推送到 GitHub。
3. GitHub Actions 运行解析器和测试。
4. 解析器生成 `site/data/notes.json`。
5. 校验通过后，Actions 将 `site` 目录发布到 GitHub Pages。
6. 校验失败时保留上一版线上网站，并在 Actions 日志中显示具体问题。

仓库采用公开可见方式，以符合用户已确认的 GitHub Pages 部署选择。

## 9. 错误处理与数据安全

- 源文件缺失或没有提取到任何知识点时，构建失败。
- 未识别分类的内容进入“待整理”，构建不失败。
- 重复标识符、无效配置结构和格式错误的精确链接会触发明确错误。
- 单个可恢复的解析异常产生警告并保留原始片段。
- 整理程序不得覆盖 `daily_note.md` 或 `practice.py`。
- 前端显示笔记内容时进行安全转义，避免笔记文本被当作可执行脚本。
- 外部链接使用安全的新窗口打开方式。

## 10. 验证方案

### 10.1 自动测试

- Markdown 标题、日期和代码块解析测试。
- Python 注释标题和代码片段解析测试。
- SQL/Python 模块分类测试。
- 典型关键词的子分类和别名测试。
- 未识别内容进入“待整理”的测试。
- 配置覆盖与精确题目链接测试。
- 生成 JSON 的结构和唯一标识符校验。

### 10.2 页面检查

- 首页、SQL 模块、Python 模块可以正常打开。
- 搜索标题、正文、代码和别名均能返回结果。
- 分类筛选与清除筛选正常工作。
- 牛客、力扣入口生成正确的搜索链接。
- 手机宽度和桌面宽度下布局均可用。
- 浅色、深色模式可切换且正文可读。

## 11. 完成标准

第一版完成需同时满足：

1. 当前两份源文件的有效内容均能在网站找到。
2. SQL 与 Python 正确分开，主要主题已归入合理分类。
3. 搜索“窗口函数”“JOIN”“循环”“列表”“函数”等典型关键词能找到对应笔记。
4. 无法分类的内容在“待整理”中可见，没有静默丢失。
5. 每个知识点有可用的牛客和力扣搜题入口。
6. GitHub Actions 测试通过后能自动发布 GitHub Pages。
7. 网站在常见手机和桌面浏览器中可浏览和搜索。

## 12. 实施顺序

1. 建立最小网站目录和解析器测试样例。
2. 实现 `daily_note.md` 解析。
3. 实现 `practice.py` 注释解析。
4. 加入分类规则、人工配置和 JSON 校验。
5. 实现页面布局、搜索、筛选和知识点详情。
6. 加入练习入口、响应式布局和深色模式。
7. 对当前全部笔记运行构建并修正分类。
8. 配置 GitHub Actions 与 GitHub Pages。
9. 在手机和电脑上完成最终验收。
